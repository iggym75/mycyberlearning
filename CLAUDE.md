# CLAUDE.md — My Cyber Learning

Public site: https://mycyberlearning.co.uk · Owner/admin: Ian Moore

## What this is
A curated library of cybersecurity podcasts, books and learning platforms (labs, CTFs, courses, certifications, events, communities and publishers' book bundles that are free or low-cost and not tied to one vendor). Visitors filter by security domain (multi-select, any/all), frequency and level; see official platform ratings and separate community votes; and suggest new resources. One admin approves, edits, hides and deletes.

## Layout
- `frontend/index.template.html` — the whole UI (vanilla HTML/CSS/JS, no framework). `/*__SEED__*/` is replaced at build time with the catalogue for offline/demo fallback.
- `scripts/build-frontend.mjs` — builds `frontend/dist/` (and syncs `data/taxonomy.json` into `worker/src/lib/`). `scripts/d1.mjs` — D1 over HTTPS for scripts, or local SQLite (`D1_LOCAL_FILE`) for tests.
- `worker/` — Cloudflare Worker (ESM, no runtime npm deps): `src/index.js` routes `/api/*`, `/auth/*`, `/admin`; everything else is static assets from `frontend/dist`. `src/lib/` has D1 helpers, email/tokens, validation and Claude tagging. Schema in `worker/migrations/`; config in `wrangler.jsonc`.
- `data/taxonomy.json` — the domain (with a `hue` for its colour), frequency, level, platform-kind and cost lists. Single source of truth; never hard-code domains elsewhere.
- `data/catalogue.json` — seed + weekly snapshot of the live catalogue (the live source of truth is the D1 `items` table).
- `scripts/refresh.mjs` + `enrich.mjs` — weekly enrichment; pure helpers in `scripts/pure.mjs` with tests in `scripts/test/`.
- `.github/workflows/` — deploy on push (wrangler), weekly refresh, daily briefing.

## Conventions
- Keep it free and card-free: Cloudflare Workers Free + D1, Resend free, GitHub Actions. Never add a service that needs a payment method without asking. Watch the free limits (10 ms CPU per request, D1 daily reads/writes).
- No frontend framework or build toolchain; keep the page a single file. Fonts from Google Fonts only.
- Item schema: `id, type (podcast|book|platform|person), name, by, desc, domains[], level[], freq, launched (YYYY or YYYY-MM), status, web, apple, spotify, amazon (Amazon Music podcast page; optional, hand-entered, host-checked), youtube, twitch (platforms with a live stream; host-checked), rss, logo, rating {v,n,asOf}, curator (shown as "MCL Pick"), isbn (13 digits, no hyphens), isbnVerified, publisher, published, bundle {name,url}, kind and cost (platforms only; taxonomy `platformKinds` / `costs`), x, bluesky, mastodon, linkedin, github, medium, discord (experts only: links to their own public profiles, exact hosts checked by `isSocialUrl`), noPhoto (experts: never fetch or show a picture), noPhotoRequested (noPhoto set at the person's request; nothing may override it), logoCredit {author, licence, licenceUrl, page, file, shareAlike, cropped, year} (Commons photos), sources[], verified, hidden, tagsLocked, statusLocked (a hand-set status/frequency the refresh keeps)`. Platforms and experts have no official rating source: only community votes show. Experts are long-standing, respected practitioners, researchers, educators and journalists (not social-media influencers); never copy their posts. An expert's picture is either a freely licensed Wikimedia Commons photo found through their Wikidata entry (public domain, CC0, CC BY or CC BY-SA only, never NonCommercial or NoDerivatives; `commonsLicence` in `scripts/pure.mjs`), credited in the viewer with photographer, year, licence and links, taken within the last eight years or so (older Commons photos are only used when there's no profile picture; the candidates mode of the Commons workflow lists each expert's newest photos to choose from), and preferred when one exists (`scripts/commons.mjs` / the Commons photos workflow pushes a review branch); or the profile picture from a profile they publish themselves (Bluesky, GitHub, Mastodon, YouTube or their own site; never X or LinkedIn, and never press, agency, speaker-bureau, event or employer team-page photos, which usually belong to a photographer), self-hosted in `frontend/covers/`, checked by eye to be them (not a pet, logo or cartoon of someone else), reverse-image-searched (TinEye/Google Lens) to make sure it isn't a stock or agency image, and dropped via `noPhoto` on request or when they have no picture of their own; experts without a picture show a topic ring (one arc per topic, colours from each domain's `hue` in the taxonomy) drawn in the page. The refresh refuses an expert picture whose file carries photographer, agency or copyright metadata (`rightsMetadata` in `scripts/pure.mjs`); it can still pick up avatars that aren't a photo of the person (cartoons, book covers), so check new ones by eye after each refresh. Never edit, trace or redraw someone's photo to get round this. Image credits are shown in the viewer, and the privacy notice's "Images we show" section gives the takedown address. A platform card links to its site, plus YouTube and Twitch when set.
- Descriptions are written in our own words (never copied from the show's or a list article's text).
- Official ratings and community votes are never combined into one number.
- Admin endpoints must be wrapped in `guard()` (worker/src/auth.js): signed session cookie (SESSION_SECRET, Worker-only) + allow-listed GitHub id + same-origin JSON for writes. All SQL uses bound parameters.
- Claude prompts treat resource text as data inside `<resource>` tags and use forced tool output constrained to the taxonomy enum.
- Caching: `/api/items` is `no-cache` for browsers (Cloudflare's zone Browser Cache TTL would otherwise stretch a short max-age to hours); the Worker's 60-second memo/edge cache carries the load. Covers are cached for a week, so a *replaced* image needs a new file name, not an overwrite. A missing static file is answered `no-store`.
- Daily briefing: `scripts/news.mjs` writes `frontend/news/<date>.json`; `scripts/send-digest.mjs` emails it; shared email/token code is in `worker/src/lib/mail.js`. Never republish show notes verbatim; only our summaries.
- My list accounts (`worker/src/account.js`, `worker/src/lib/webauthn.js`, `worker/src/account-email.js`): passkey sign-in with user verification required; recovery by a one-time code or an emailed single-use link. Never add password sign-in. Name and email are optional; an email is only used after it's confirmed from a link sent to it. The daily briefing and new-feature emails are separate, unticked opt-ins with a recorded consent and one-click unsubscribe; creating an account never subscribes anyone. Changing the email needs a recent passkey sign-in. Update emails are written in Admin → Send an update and sent by `updates.yml` (`scripts/send-updates.mjs`) within the day's email allowance after the briefing. Keep `scripts/test/account.test.mjs` passing (it signs real ES256/Ed25519/RS256 credentials). Signed-out visitors' lists live in localStorage and are merged on sign-in.
- Personal data rules (see SECURITY.md): consent-only, minimum fields, no IPs or identifiers stored, escape everything in emails, GET never changes state, keep the privacy notice in the page in step with any change.

## Commands
- `npm test` — unit tests (must pass before deploy)
- `npm run build` — build the site
- `npm run refresh:dry` — preview enrichment without writing
- `npm run seed` / `npm run export` — push catalogue to / pull it from D1 (need `CLOUDFLARE_ACCOUNT_ID`, `D1_DATABASE_ID`, `CLOUDFLARE_API_TOKEN`, or `D1_LOCAL_FILE`)
- `npm run dev` — local site + Worker with wrangler; `npm run deploy` — manual deploy

## Workflow for changes
Make changes on a branch and open a PR; the Deploy workflow tests every PR but only deploys `main`. Run `npm test` and `npm run build` before proposing changes.
